## 一、修复上轮集成测试遗留问题（6 个失败 → 全绿）

上轮把 Ring B 从 `@Sql` 改成整段重放 `schema.sql` 后未验证，`mvn verify` 实际 6 个用例失败。根因与修复：

| 失败用例 | 根因 | 修复 |
|---|---|---|
| `CourseMapperIT.listByInstructorFiltersStatus` | **`insertCourse` XML 漏入库 `status` 列**，实体设 published 也落库为 draft | `insertCourse` 增加 status（null 时用 `DEFAULT`）；`updateCourse` 同步回写 status |
| `CourseMapperIT.searchByKeyword` | 同上（status 未持久化）；另：`simple` 分词器按空白切分，中文整段是一个 token | 修复 status 持久化；测试改用独立英文词 `Zig` 作关键字 |
| `CourseMapperIT.insertAndSelectDetailRoundTrips` | jsonb 输出规范化空格（`{"chapters": []}`）与紧凑字符串不等 | 断言改为 `ObjectMapper.readTree` JSON 语义比较 |
| `CourseMapperIT.deleteWithOrderFails` | 测试逻辑错误：从未建订单却期望删除抛错；且期望 Mapper 返回抛异常（实际返回 null） | 用真实 JDBC 插入 orders 行，断言 `BusinessException`；新增 `deleteWithoutOrderSucceeds`（删除成功路径） |
| `CategoryMapperIT.treeBuildsHierarchy` | 未考虑 schema 种子数据（前端开发/后端开发 2 个根），按总数断言必然失败 | 改为按名称定位本次创建的节点 |
| `CategoryMapperIT.deleteWithCoursesFails` | 测试逻辑错误：未创建关联课程却期望抛错 + 期望 Mapper 抛 NotFoundException | 真实创建关联课程断言 `BusinessException`；新增 `deleteEmptyCategoryRemovesRow`（成功路径） |

另：`CourseMapperIT` 新增 `countByInstructorIdCountsOnlyThatInstructor`（覆盖讲师删除校验迁移后的计数逻辑）。

## 二、代码冗余清理

1. **`countCoursesByInstructorId` 双份挂载**：InstructorMapper 与 CourseMapper 各有一份相同 SQL（InstructorMapper 注释自标「应迁移到 CourseMapper」）。已移除 InstructorMapper 版本，`InstructorServiceImpl.delete()` 改注入 `CourseMapper.countByInstructorId`，单元测试 mock 同步迁移。
2. **`keywordFilter` SQL 片段形同虚设**：InstructorMapper.xml 定义了 `<sql id="keywordFilter">` 却未引用，`list`/`count` 各自内联同一份 `<if>`。已改为两处 `<include refid="keywordFilter"/>`。
3. **集成测试 `applySchema()` 三处逐字节重复**（Instructor/Course/Category IT）：抽公共基类 `AbstractMapperIT`（`@ActiveProfiles("it")` + `@SpringBootTest(webEnvironment = NONE)` + 整段重放 DDL），三个 IT 各自瘦身 ~20 行，且统一为无 Web 环境（少起一个 Spring 上下文）。
4. **死导入**：`CourseFrontController` 未使用的 `InstructorService`/`InstructorVO` 导入删除。
