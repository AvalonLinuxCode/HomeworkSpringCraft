## 数据库准备（已完成）

用 DBX 连接 `Local-PG18`（`127.0.0.1:5433`，超级用户 `postgres`）执行：

```sql
CREATE ROLE edu_user LOGIN PASSWORD 'edu_password';
CREATE DATABASE edu_platform      OWNER edu_user;   -- 开发库
CREATE DATABASE edu_platform_test OWNER edu_user;   -- 集成测试专用
```

`edu_platform` 的 DDL 必须**以 edu_user 身份**执行，否则表属主是 `postgres`，应用连上后报「对表 instructor 的权限不足」：

```bash
cd D:/myDB/postgresql_Data/bin
PGPASSWORD=edu_password ./psql.exe -h 127.0.0.1 -p 5433 -U edu_user -d edu_platform \
  -v ON_ERROR_STOP=1 -f "E:/AllProject/TEST/HomeworkSpringCraft/docs/Design_Description/schema.sql"
```

验证结果：5 张表（`users/instructor/category/course/orders`）、3 个枚举、5 个 `updated_at` 触发器、种子数据 1/2/4/2/0 行，表属主全部为 `edu_user`。

## 设计取舍

1. **开发库与测试库分离**。集成测试 `@BeforeEach` 会 `DROP TABLE ... CASCADE` 重放 DDL，若与开发库共用会清空开发数据。`edu_platform_test` 专供 Ring B，可随时丢弃。
2. **不引入 Testcontainers**。本机已装 PG 18，且 Docker 守护进程未常驻；直接连本地实例，`mvn verify` 零额外依赖。
3. **测试库不自建**。数据库/角色属于环境准备（一次性的运维动作），测试只负责建表，避免测试代码里塞超级用户凭据。
4. **保留 `spring.sql.init.mode: never`**。启动绝不自动建表；DDL 只有 `schema.sql` 一份事实来源，由测试重放或人工执行。

## 环境注意（本机）

- 本机 Maven 3.9.9 位于 `~/tools/apache-maven-3.9.9`，需先 `export MAVEN_BASEDIR='E:\AllProject\TEST\HomeworkSpringCraft\edu-platform'`。否则 Git Bash 下 `mvn` 脚本的 `find_maven_basedir` 会因 `pwd` 返回 `E:\` 而**死循环**（不是编译慢）。
- `psql.exe` 必须用 Windows 路径调用（msys 路径会报 `invalid binary`），或先 `cd` 到 `D:/myDB/postgresql_Data/bin` 再 `./psql.exe`。
- DBX MCP 默认只读，写操作需在 DBX 设置里把该连接 MCP 权限提到 write/high-risk。
